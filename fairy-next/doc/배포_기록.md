# 당신편 무료 배포 가이드 (간결판)

> 작성: 2026-06-14 / 상태: **아직 미실행 — 다음에 배포할 때 따라 할 계획서**
> 구성: 프론트=Vercel(무료) · 백엔드=Render(무료) · DB=TiDB Cloud or Railway(무료). MySQL 유지.
> ⚠️ 당신편 특이점: **실시간 채팅(Socket.io)** 때문에 백엔드는 WebSocket 지원 호스팅이어야 함 → Render OK.

## 0. 이게 다 뭐야? (식당 비유)
- **GitHub**: 코드 원본 보관소 = 설계도 창고
- **Vercel**: 화면(프론트) = 손님이 보는 매장/메뉴판
- **Render**: 백엔드(API+소켓) = 주문 처리하는 주방
- **TiDB/Railway**: DB = 식자재 창고
- 흐름: 손님(브라우저) → Vercel 화면 → Render 백엔드 → DB창고
- 핵심: 이 넷이 서로의 "주소"로 연결돼야 돈다. 하나라도 끊기면 화면만 뜨고 데이터 안 나옴.

## 1. 전체 구조
```
GitHub(fairy 저장소)
   ├─ fairy-next/         → Vercel (프론트, Root Directory = fairy-next)
   └─ fairy-next/server/  → Render (백엔드+Socket.io)
                              └─ TiDB/Railway (DB, fairy)
```

## 2. 작업 순서

### STEP 0. 사전 준비
- GitHub 저장소에 push (fairy-next 포함)
- `.gitignore` 에 `.env`, `node_modules`, `server/uploads/img/*` 제외 확인
- 모노레포라 Vercel/Render 각각 Root Directory를 지정해야 함

### STEP 1. DB 만들기 (TiDB Cloud 무료 Starter)
1. tidbcloud.com 가입 → Create → **Starter(무료, $0)** (Dedicated 아님 주의)
2. Region: Tokyo / Connect 에서 접속정보 확인 (Host/User/Password)
3. DBeaver 등으로 접속 → `server/db/schema.sql` → `seed_categories.sql` → `seed.sql` 실행
   (또는 로컬에서 .env를 클라우드 DB로 바꾸고 `node db/run-sql.js`)
4. TiDB는 SSL 필요 → 백엔드 .env 에 `DB_SSL=true`

### STEP 2. 백엔드 배포 (Render)
1. render.com 가입 → New → **Web Service** → GitHub 저장소 연결
2. **Root Directory: `fairy-next/server`**
3. Build: `npm install` / Start: `node server.js` / Instance: Free
4. Environment(환경변수) 등록:
   - `DB_HOST` `DB_PORT` `DB_USER` `DB_PASSWORD` `DB_NAME=fairy` `DB_SSL=true`
   - `JWT_SECRET` (길고 무작위)
   - `CORS_ORIGIN` = (STEP 3에서 나온 Vercel 주소, 콤마구분)
5. 결과 주소 예: https://dangsinpyeon-api.onrender.com  → /api/health 확인
   - ⚠️ Render 무료는 미접속 시 잠듦 → 첫 로딩 10~50초 가능(정상)

### STEP 3. 프론트 배포 (Vercel)
1. vercel.com 가입(GitHub) → Add New → Project → 저장소 Import
2. **Root Directory: `fairy-next`** / Framework: Vite(자동)
3. Environment Variable:
   - `VITE_API_BASE` = STEP 2의 Render 백엔드 주소 (예: https://dangsinpyeon-api.onrender.com)
   - (지도 쓰면) `VITE_KAKAO_MAP_KEY`
4. Deploy → 결과 예: https://dangsinpyeon.vercel.app
5. SPA 라우팅 404 방지: `fairy-next/vercel.json` 에 rewrites 추가
   ```json
   { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
   ```

### STEP 4. 서로 연결 마무리 (가장 자주 실수하는 곳)
- 백엔드 `CORS_ORIGIN` ← Vercel 주소 넣고 Render 재배포
- 프론트 `VITE_API_BASE` ← Render 주소 (소켓도 이 주소 사용 — lib/socket.js가 API_BASE 사용)
- 둘 다 맞아야 채팅(WebSocket)·API 동작. CORS 에러 = 이 단계 누락.

## 3. 자주 나는 문제
- 화면은 뜨는데 데이터 X → VITE_API_BASE 오타 / 백엔드 잠듦 / CORS_ORIGIN 누락
- 채팅 연결 안 됨 → 소켓이 잘못된 주소로 붙음(VITE_API_BASE 확인), Render가 WS 허용하는지
- 401 로그인 안 풀림 → JWT_SECRET 이 로컬↔배포 다르면 기존 토큰 무효(정상). 다시 로그인.
- 이미지 안 보임 → Render 무료는 디스크 비영속(재배포 시 uploads 날아감). 운영은 Cloudinary 등 권장.
