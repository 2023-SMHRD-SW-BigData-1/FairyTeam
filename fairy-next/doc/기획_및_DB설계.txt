================================================================================
0. 한 줄 요약
================================================================================
당근/번개장터 같은 중고거래 마켓인데, 핵심 차별점은 "편의점 위탁거래".
판매자가 약속한 편의점에 물건을 맡기면 → 구매자가 아무 때나 픽업.
대면 없이, 시간 압박 없이, CCTV·점원이 지키는 곳에서 안전하게 거래.
위치기반(카카오맵)으로 두 사람 사이 "중간 지점 편의점"을 추천.


================================================================================
1. 요구사항 (기능 범위)
================================================================================

[1-1] 핵심 컨셉
 - 일반 중고마켓과 다른 점: 거래 장소가 "편의점"이고, "위탁(맡김→픽업)" 흐름이 있다.
 - 안전장치: 24시간 운영 + CCTV + 점원(증인) → 직거래 사기·범죄 예방.
 - 위치기반: 내 동네/판매자 동네의 중간 지점에서 가까운 편의점을 찾아준다.
 - 같은 점: 회원 / 상품등록 / 검색·카테고리 / 찜 / 실시간 채팅.

[1-2] 사용자 기능 요구사항
 (F-01) 회원가입 / 로그인 (이메일+비밀번호, JWT)
 (F-02) 카테고리/상품 둘러보기 (대·중·소 3단 카테고리, 검색, 정렬)
 (F-03) 상품 상세 보기 (이미지 갤러리, 상태/교환/수량, 조회·찜수, 연관상품)
 (F-04) 상품 등록 / 수정 / 삭제 (사진 업로드, 3단 카테고리, 상태·교환·수량)
 (F-05) 찜하기 / 찜 목록 (정렬·선택삭제)
 (F-06) 실시간 채팅 (판매자↔구매자, Socket.io)
 (F-07) 위탁거래 요청 → 편의점 선택(거리순/중간지점) → 위탁 → 픽업
 (F-08) 마이페이지 (내 정보 수정, 내 판매상품)
 (F-09) 최근 본 상품 (사이드바)

[1-3] 미구현 / 의도적 제외 (원본의 번개장터 복붙 흔적은 제외)
 - 결제 API (현재 위탁거래 상태머신만, 실결제 X)
 - 로그인 탭(ID/일회용번호/QR) — 번개장터 복붙이라 제외, 이메일+JWT로 대체
 - 상점후기 / 팔로잉 / 팔로워 (찜 페이지에 탭 자리만, 백엔드 없음)
 - 카카오 지도 시각화 (키 받으면 추가, 현재는 거리순 리스트로 동작)

2. 페이지 목록 (라우트)
================================================================================
 /                      홈 — 배너 캐러셀 + 카테고리 + 상품그리드 + 우측사이드바(찜한/최근본/TOP)
 /login                 로그인
 /signup                회원가입 (이메일·비번·이름·닉네임·생년월일·전화)
 /products/:id          상품 상세 (번개장터식: 안전거래배지·스펙·연관상품)
 /products/new          상품 등록 (3단 카테고리 캐스케이더 + 상태/교환/수량)
 /products/:id/edit     상품 수정
 /products/:id/trade    위탁거래 요청 (편의점 거리순/중간지점 선택)         [로그인]
 /trades                내 위탁거래 (약속→위탁→픽업 상태, 역할별 버튼)        [로그인]
 /favorites             마이샵 (탭: 상품/상점후기/찜/팔로잉/팔로워)           [로그인]
 /chat                  채팅방 목록                                          [로그인]
 /chat/:roomId          실시간 채팅방 (Socket.io)                            [로그인]
 /mypage                마이페이지 (정보수정 + 내 판매상품)                   [로그인]

3. DB 설계 (MySQL/MariaDB, InnoDB, utf8mb4) — 9개 테이블
================================================================================
 상세 DDL은 server/db/schema.sql, 사람이 읽는 명세는 doc/db/db-table.txt 참고.

 [3-1] category   카테고리 (대/중/소 3단, code 자연키)
   code(PK) name emoji parent_code depth(1대/2중/3소) sort_order is_active
   - 코드규칙: 대=x00 / 중=xy0(부모 x00) / 소=xyz(부모 xy0)
   - 원본 CategoryList에서 추출: 대11 / 중34 / 소161 = 206개

 [3-2] member     회원 (비번 BCrypt 해시 — 평문저장 폐기)
   id(PK) email(UQ) password_hash name nickname(UQ) phone birth_date
   avatar_url region_name lat lng role(MEMBER/ADMIN) status 감사컬럼 deleted_at

 [3-3] store      편의점 (위탁 픽업 장소) ★당신편 핵심
   id(PK) brand(GS25/CU/세븐일레븐/이마트24) name address lat lng is_partner

 [3-4] product    상품
   id(PK) seller_id(FK member) category_code(FK category) title description
   price is_negotiable condition_type(USED/NEW) exchangeable quantity
   status(ON_SALE/RESERVED/SOLD) thumbnail_url view_count
   region_name lat lng 감사컬럼 deleted_at

 [3-5] product_image  상품 사진 여러 장 (product 삭제 시 CASCADE)
   id(PK) product_id(FK) url sort_order

 [3-6] favorite   찜 ((member,product) 복합 PK = 중복 찜 방지)
   member_id(FK) product_id(FK) created_at

 [3-7] chat_room  채팅방 (상품 1개에 구매자-판매자 1:1, UQ(product,buyer))
   id(PK) product_id(FK) buyer_id(FK) seller_id(FK) created_at

 [3-8] chat_message  채팅 메시지 (read_at = 안읽음 표시)
   id(PK) room_id(FK) sender_id(FK) content image_url emoticon read_at created_at

 [3-9] trade      위탁거래 ★당신편 핵심
   id(PK) product_id(FK) seller_id(FK) buyer_id(FK) store_id(FK) price
   status(REQUESTED→CONSIGNED→DONE / CANCELED) requested_at consigned_at done_at
   - 상태 전이에 맞춰 product.status 동기화(RESERVED/SOLD/ON_SALE)


================================================================================
4. 위탁거래 상태 흐름 (당신편의 심장)
================================================================================
 구매자가 편의점 선택 → 거래요청        : trade=REQUESTED, product=RESERVED
 판매자가 편의점에 물건 맡김            : trade=CONSIGNED  (픽업 대기)
 구매자가 편의점에서 픽업               : trade=DONE,      product=SOLD
 (완료 전) 어느 쪽이든 취소             : trade=CANCELED,  product=ON_SALE 복귀
 ※ 권한: 위탁=판매자만 / 픽업=구매자만 / 취소=양쪽. 전부 트랜잭션 + 본인검증.


================================================================================
5. 테스트 케이스 (핵심)
================================================================================
 (TC-01) 회원가입 — 이메일/닉네임 중복 시 409
 (TC-02) 로그인 — 틀린 비번/없는 계정 동일 메시지(계정 존재 노출 방지)
 (TC-03) 상품 등록 — 비로그인 401, 등록자=판매자
 (TC-04) 상품 수정/삭제 — 본인 아니면 403 (소유자 검증)
 (TC-05) 카테고리 필터 — 대분류 선택 시 하위 중·소 상품 전부 포함
 (TC-06) 찜 — 같은 상품 중복 찜 무시(멱등), 토글
 (TC-07) 채팅 — 참여자 아닌 방 접근 403, 내 상품엔 채팅 불가
 (TC-08) 위탁거래 — 구매자가 위탁 시도 시 403("판매자만 위탁")
 (TC-09) 위탁거래 — 픽업 완료 시 product=SOLD 전환
 (TC-10) 편의점 중간지점 — 두 좌표 중간에서 가까운 순 정렬

 ※ 위 TC들은 개발 중 실제 API 호출로 검증 완료(진행상황 문서 참고).
